# 2026-08-19 会话（轮次三）：M2 手——input.* 四原语 + 事件订阅推送

## Plan + Spec（已与用户确认）

背景：M1 眼睛已睁（三感知工具真机验收过）。M2 是"风险前置"原则的关键一步：输入注入保真度最先验证。验收 = 纯脚本重放"按 E 开背包 → 放木头 → 合成工作台"（项目可行性证明）。

### 五项已确认设计决策

1. **事件层注入**（非动作层）：模拟 GLFW 事件回调（KeyboardHandler.keyPress / MouseHandler.onPress/onMove / charCallback），输入走与真人完全相同的分发管线——Mod GUI 可被操作的前提，规格 §5.2"像人一样操作"
2. **拖拽 = 两次点击**：MC GUI 物品操作本质"点源格拾起 + 点目标格放下"，不做按住移动
3. **安全模型**：输入限频 ~20 次/s（防失控）；每条输入写审计日志；GUI 打开时的 click 自动截图留证（可配置）
4. **事件最小集**：events.subscribe 落地 + chat（INFO）/ health 变化（WARNING，阈值下 CRITICAL）/ death（CRITICAL）/ screen 开关（WARNING）；notification 帧推送，seq 递增，基础节流
5. **创造模式背包无 2×2 合成格** → 演示脚本先 input.text 输 `/gamemode survival` 再操作（方案 a，用户采纳推荐）

### 任务分解

| # | 任务 | 交付物 | 验收 |
|---|---|---|---|
| M2-A | input.* 四原语（事件层注入 + 限频 + 审计 + GUI 点击留证） | `InputTools.java` + 纯逻辑可测部分 | 真机：按 E 开背包，截图确认（风险前置单点验证） |
| M2-B | 事件系统（三源 + notification 推送 + 节流）+ 轻量 getGuiState（screen 类型/开关） | `EventsSystem.java` 等 + `GuiStateTool.java` | Python 订阅后收到事件、seq 递增；getGuiState 报告背包开/关 |
| M2-C | 演示脚本：/gamemode survival → E 开背包 → 放 4 木头入 2×2 → 取工作台 | `sirius-brain/scripts/m2_demo.py` | **完整流程纯脚本零人工，截图为证** |
