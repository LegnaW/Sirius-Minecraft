# 2026-08-21 会话：M4.1 修复轮（反射层独立存活 + 自然转头）

## Plan + Spec（已与用户确认）

### 目标（用户原话转写）

1. **机器人没有任何上层指令输入的前提下，完全靠反射层尽量保持不死**（"尽量"——诚实目标：记录死亡原因而非承诺零死亡）
2. **移动要自然转头**——现在是"固定视角的平移"（strafe 平移），头应该转向前进方向（固定角速度）

### 新验收标准（反射层独立存活；2026-08-21 用户修正：分段制，消除饱食度变量）

1. **分段场景压测**（取代连续 10 分钟——连续跑会被饥饿拖死，属资源约束非反射层缺陷）：五场景各 2 分钟独立压测——①怪群围攻（僵尸+溺尸混合 3-5 只）②深水反复推入 ③火（点燃脚下及周围）④卡位（1 宽坑/围方块）⑤综合混灾；每场景开始前 OP 补状态（instant_health + saturation 持续），场景间重置；每场景记录反射触发统计/血量曲线/死亡归因
2. **边界声明**（诚实口径）：反射层目标范围 = 突发危险的即时自救（溺水/着火/围攻/卡位）；慢性消耗（饥饿/低饱食）不在职责内——"进食反射"记 backlog（执行器层协作，M4.2/M5 候选）
3. **转头自然性**：Baritone 行走时头转向前进方向（固定角速度），不再平移；急转场景（逃离）转身可感
4. 修复项 1/3/4 各自回归：连发命令不合并；死亡播报真实出现在聊天；长按不再 -32010
5. pytest/冒烟全绿不破

#### 核心内容

- **五缺陷处置**：①命令竞态——锁下沉 `BridgeClient` 客户端级 + GUI 确认时序（真机 10 条连发 5.19s 零合并、位移 14.9 格）；②移动不转头——根因是 Baritone 构建自身行走不转头，bridge `MovementLook` 补位（真机 43 样本 |yaw−运动方向| 中位 0°/P90 8°）；③死亡播报——`chat.send` 进程内直发（死亡屏开着也真实进聊天，端到端实证）；④令牌桶——"按 tick 计费"证伪、无需改码（见下）；⑤cooperative×Baritone——`#pause`/`#resume` 配对（仅 movement_active 时 pause，真机 Baritone 回执实证）。
- **T6 分段存活压测（用户修正的验收）**：五场景各 120s、零任务消费、饱和效果消除饥饿变量——火/卡位/综合 PASS，怪群 DEATH（L1 禁攻击设计边界，反射链全部正确仍死）、深水首轮 DEATH（占空比缺陷）修后回归 PASS。两次死亡全归因。
- **压测引出的计划外修复 ×2**：换气占空比（400ms/500ms 歇 → 按满 800ms）；`safe_command`（低血 #stop 被 GUI 拒绝抛异常会跳过直发警报与 urgent 注入——保命链的停止动作不该有能力打断警报）。
- **协议 1.2→1.3**：chat.send + getStats yaw/pitch；测试 pytest 339→**351**、冒烟 353→**369** 全绿。

#### 遇到的问题与处理

1. **两个预设假设被证据推翻（诚实记录，spec 排查方向修正）**：
   - **TurnController 压制说（T2，spec 缺陷 #2 的怀疑）**：原怀疑 T6 TurnController 与 Baritone 旋转互相覆盖（两者都逐 tick 写 yRot）。证据推翻：M4-rerun 130 格长走全程 `sirius_bridge.log` 审计**零条 look/lookAt/turn 写入**（TurnController 压根没活跃，且收敛即注销、自过期上限存在）；真因是 **Baritone（baritone-standalone-neoforge-1.11.2.jar 构建）行走自身不转头**——WASD 组合平移、相机全程冻结。修复方向由"归一两个旋转源"改为"bridge 补位"（MovementLook），并留 2° 死区——若 Baritone 将来自己转头，目标一致时控制器自然静默。
   - **令牌桶按 tick 计费说（T4，M4-rerun 的推断）**：源码所有计费点（input.key/text/mouseMove/click/dig）都是 `tryAcquire(1)` 按调用计费；真机裁决：1500ms SHIFT 长按 + 19 并发 tap **19/19 全过**（30 并发齐发观测到拒绝——限流器本身正常）。M4-rerun 的 -32010 真因是**演示脚本自身不等待的管道化并发**（input.* 主线程 ~50ms/个，串行 await ~5/s 追不上 20/s 补充，只有 fire-and-forget 齐发才打得穿）。反射层全部 await 串行（≤2/s），无桶风险——**无需改码**。
2. **上轮"播报×3"矛盾复查**：M4.md 记死亡播报 PASS ×3，验的其实是 wire 层 SENT；游戏聊天可见性当时依赖轮询抢在死亡屏渲染前——时序侥幸。M4-rerun 的观测（wire 已发、聊天无行）才是稳定真相。本轮直发通道端到端实证（重启后世界恰停死亡屏，播报真实进聊天且不自动重生）。
3. **T6 压测引出两个计划外修复**（spec 未列）：深水占空比缺陷（首轮 DEATH 归因后修+回归 PASS）；safe_command（深水回归轮暴露 -32002 拒绝打断保命链）。教训：压测设计里"场景前补状态"的 GUI 操作会占用聊天屏，与反射 #stop 产生新的竞争面。
4. **版本勘误**：MC 实为 1.21.1 / NeoForge 21.1.248——mods 里 baritone jar 文件名的 "1.11.2" 是 Baritone 构建名非 MC 版本（此前文档口径含混）。
5. **压测世界的作弊授权**：「新的世界」原作弊关闭（/effect 不可用）——探针 GUI 自动化（ESC→对局域网开放→作弊:开启→开启，全走 getGuiState 控件坐标）成功开启，饱和消除饥饿变量达成。
6. **运维**：新 jar 需 quickPlay 重启加载（HMCL 日志 xz 解压提取启动命令，令牌仅落 %TEMP% 用后即删）；窗口最小化废 mouseMove（探针内置 ShowWindow 恢复）；mouseMove 回包 GUI 坐标键为 `gui_scaled`。
