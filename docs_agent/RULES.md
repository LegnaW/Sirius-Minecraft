# Sirius 工作规则（RULES）

> **每次开工前必读本文件。** 它是工作方式的唯一权威：怎么开工、怎么实施、怎么收尾、每份文档管什么。
> 仓库根 `AGENTS.md` 是 agent 自动加载的入口，指向本文件。
> 修订需与用户确认后进行，记录在文末修订表。
> 创建：2026-08-18

## 0. 核心循环（一句话）

**读规则 → 读现状 → 出方案 brainstorm → 落 spec → 按 spec 实施 → 过 6 项门禁 → 等用户反馈开下一轮。**

## 1. 全局原则：双层文档分工

| 目录 | 受众 | 要求 |
|---|---|---|
| `docs_agent/` | agent 阅读 | 确保读后**准确理解情况**：精确、完备、可追溯 |
| `docs_human/` | 人类阅读 | 突出重点、**可读性高**，让用户快速掌握项目精髓；内容不得与 docs_agent 权威冲突 |

## 2. 开工前（按序读完再动手）

1. **本文件**（RULES）
2. `DEVELOPMENT.md` —— 环境、命令、schema 链、常见坑
3. `dev-journey.md` —— 历史决策叙事（为什么走到今天）
4. `session/` 最近 1-2 篇日志 —— 上轮做了什么、留了什么尾巴
5. `PROGRESS.md` —— 跨会话状态锚点（做到哪了、接下来干什么）
6. 与本轮需求相关的规格章节（`sirius-technical.md` 对应 §、`protocol-neko-mapping.md` 等）

## 3. 开工：方案先行，禁止直接写码

- 针对本轮需求，先给出**【设计思路】+ 简单核心实现片段**（接口签名 + 关键逻辑；文档类任务则为结构骨架）
- 与用户 brainstorm，**确定开工方案后才继续**——未确认不动手
- 大任务沿用主管模式（技术规格 §10）：主会话拆解/验收，实现派发子代理，任务另留 `reports/<里程碑>-<任务>.md` 交接报告

## 4. spec 落当日 session 文件

确认后的方案写进 `docs_agent/session/YYYY-MM-DD.md`，自包含（执行者无会话历史）：

```
# YYYY-MM-DD 会话：<轮次名>
## Plan + Spec（已与用户确认）
  背景 / 结构或接口设计 / 任务分解表（#、任务、交付物、验收）
  关键设计（各部件骨架）+ 核心代码片段（带注释说明思路）
## 收尾日志（完成后补写）
  文件改动表（每个文件→改动→为什么）/ 核心内容介绍 /
  遇到的问题与处理 / 门禁结果 / 未完成与下一步
```

## 5. 实施中

- **严格按确认的方案执行**；出现方案未覆盖的情况，先暂停问用户
- 若实现偏离 spec（设计缺陷、需求变化、与用户讨论后改方案）：**先同步更新 `docs_agent/` 对应章节（技术规格/DEVELOPMENT/RULES），再继续写码**
- 代码注释写清"为什么这么改"，不写"改了什么"

## 6. 收尾门禁（硬性，全过才算本轮完成）

| # | 检查 | 通过标准 |
|---|---|---|
| 1 | 代码与文档一致性 | spec/日志约定的接口、行为与实现逐项比对一致；文档引用的路径/代码片段真实存在 |
| 2 | 跑通验证 | 从零按 README/DEVELOPMENT 命令跑通（pytest / gradlew build 等），本轮改动可运行且不破坏既有功能 |
| 3 | tmp 清理 | 验证用的临时环境/脚本/下载物删除干净 |
| 4 | 当日日志 | session 当日文件补全（文件改动表/核心内容/问题与处理/下一步） |
| 5 | 改动摘要 + 小步提交 | 给用户摘要；按逻辑单元小步提交，提交信息写清"为什么" |
| 6 | overall.md 维护 | 技术细节有变动时同步 `docs_human/overall.md`（代码片段必须与真实文件对应） |

## 7. 循环

门禁全过后，**等用户反馈**决定是否开启下一轮（重复全部流程）；除非用户明确说"完成/结束"，否则不提前收工。

## 8. 文档作用地图（权威表）

| 文档 | 受众 | 作用 | 更新时机 |
|---|---|---|---|
| **RULES.md（本文件）** | agent | 工作方式唯一权威：流程/门禁/文档地图 | 流程变更（需用户确认） |
| 根 `AGENTS.md` | agent | agent 自动加载入口，指向 RULES | 与 RULES 同步 |
| `DEVELOPMENT.md` | agent | 操作手册：环境/命令/schema 链/常见坑 | 环境或操作变化时 |
| `dev-journey.md` | agent | 历史决策叙事（为什么） | 重大决策落地时追加 |
| `PROGRESS.md` | agent | 跨会话状态锚点（做到哪/接下去） | **每轮结束必更** |
| `session/YYYY-MM-DD.md` | agent | 当轮 plan+spec + 收尾日志 | 每轮一份 |
| `sirius-design.md` | agent | 设计权威：理念与架构 | 设计变更时 |
| `sirius-technical.md` | agent | 技术规格权威：接口/数据结构/路线图 | 接口规格变更时（改码前先改这里） |
| `protocol-neko-mapping.md` | agent | 自研协议 ↔ NEKO 帧映射 | 协议帧变更时 |
| `reports/<里程碑>-<任务>.md` | agent | 子代理任务交接报告 | 每个派发任务完成时 |
| `../docs_human/overall.md` | 人 | 全局技术文档：从调用栈到细节设计（贴真实代码） | 每轮技术变动时（门禁 6） |
| 根 `README.md` | 人/访客 | 项目一句话 + 文档入口 | 里程碑变更时 |
| `sirius-brain/README.md`、`sirius-bridge/README.md` | agent | 各子项目使用细节 | 子项目行为变更时 |
