## 排查结论（已定案）

- **T1 命令竞态根因**：两层叠加。
  1. 命令串行锁只存在于 `LoopClient`（loop 级）；`m4_flee_walk_probe.py` 等探针用 **raw `BridgeClient`** 建 `Primitives`（`Primitives(client)`），与调度器（走 tools_client 锁）的 #stop/#goto 并发 → wire 上两条 T→text→ENTER 交错 → 游戏聊天框内 "#stop"+"#goto" 合并成一行（M4-rerun 00:41:01 `Command not found: stop#goto` 的成因）。
  2. `BridgeClient.command` 的时序全是拍定时数（0.4/0.3/settle），无"聊天框确实打开/确实关闭"的确认。
  - 修法：锁下沉到 `BridgeClient.command`（客户端级，所有发送方共用）+ T 后等 Chat 屏确认（开不了重试一次 T，仍不开则报错拒绝盲发——顺带消灭"ENTER 误点 GUI 按钮"风险）+ ENTER 后等聊天屏关闭再返回。聊天框已开时复用（跳过 T）。
- **T2 转头根因**：M4-rerun 00:48:16–00:49:07 的 130 格 Baritone 长走全程，`sirius_bridge.log` 审计里 **零条 look/lookAt/turn 写入**（只有 getStats/world.query 轮询）——相机冻结不是 TurnController 压 Baritone（它压根没活跃），是 **Baritone 自身行走不转头**（用 WASD 平移组合走路）。TurnController 收敛即注销、自过期上限 360/speed+1.5s，不存在"驻留"问题。
  - 修法（bridge 侧 MovementLook）：身体在动（水平速度>阈值）且无显式转头任务时，按固定角速度把 yaw 转向速度矢量方向（pitch 不碰）；显式 lookAt/dig 瞄准（活跃 Turn）优先，MovementLook 让位。getStats 补 yaw/pitch 字段（增量，协议 1.3），兼作诊断数据源与 unstuck 扇形基准。
- **T4 令牌桶**：源码所有计费点（input.key/text/mouseMove/click/dig）都是 **每次调用扣 1 令牌**（`guard.tryAcquire()` 在调用入口一次），与 M4-rerun "长按按 tick 计费"的推断矛盾。真机实验裁决部署 jar 实际行为（见 T4 段）。若部署 jar 已是按调用计费，则当时 -32010 的来源是演示脚本高频循环调用本身。
- **版本勘误**：MC 实为 **1.21.1 / NeoForge 21.1.248**（mods 里 `baritone-standalone-neoforge-1.11.2.jar` 的 "1.11.2" 是 Baritone 构建名）。#pause 可用性按 1.21.1 真机实测。

## 实现记录

### 代码（全部完成，pytest 350 / 冒烟 369 全绿）

**T1 命令竞态（brain：`bridge/client.py` + 测试）**
- `BridgeClient.command` 持**客户端级命令锁**（`_command_lock`）——同实例所有发送方（探针 Primitives / 反射 #stop/#goto / 任务播报）的 T→text→ENTER 序列 wire 上不可能交错。LoopClient 锁保留（echo+注视窗口的原子性），锁序 loop→client 无死锁。
- 时序确认替代拍定时数：T 后轮询 getGuiState 等聊天屏打开（其他 GUI 占用 → 报错拒绝盲发，杜绝"文本进任意 GUI + ENTER 误点按钮"；连续无屏且应答正常 → 按旧行为放行；身体无 screen_open 字段 → 退回 M2-D 定时等待）；ENTER 后等聊天屏关闭（关不掉 = 发送失败 → ESC 丢弃残留防串扰 + 报错）。
- 测试：`TestCommandRace` 三条（并发不合并 / 背靠背三连发不合并 / GUI 占用拒绝盲发），`TestCommand` 两条按新契约更新。
- 附带修复：`m4_flee_walk_probe.py` 的 Primitives 改挂 `agent.tools_client`（原 raw client 是事故根因之一）。

**T4 令牌桶（裁决：无需改码，实测+文档）**
- 源码所有计费点（input.key/text/mouseMove/click/dig）均 `tryAcquire(1)` 按调用计费。
- **旧 jar 真机实测**（m41_live_checks.py t4）：1500ms SHIFT 长按 + 19 并发 tap **19/19 全过**——长按只占 1 令牌坐实，"按 tick 计费"证伪；30 并发齐发有 -32010 拒绝——限流器工作正常。当时 M4-rerun 的 -32010 归因：演示脚本自身并发打爆（input.* 主线程管道 ~50ms/个，串行调用 ~5/s 远追不上 20/s 补充，只有不等待的管道化齐发才可能打穿）。
- 反射层无风险：换气反射 await 串行 ≤2/s。

**T5 cooperative×Baritone 裁决（brain：`reflexes.py`）**
- `ReflexScheduler.pause_baritone()/resume_baritone()`（#pause/#resume，幂等、失败只记日志）；`BreathReflex.act` 在 `movement_active` 时先 pause 后 try/finally resume——消灭"换气浮起→水下 GoalBlock 再按下"拉锯（M4-rerun §1 溺亡事故）；#stop 已撤目标后 #resume 是无害空操作。
- 裁决理由：#pause 保目标续走优于 #stop+不重启（后者损失 walk 原语续走）；**真机实测 #pause/#resume 被 Baritone（baritone-standalone-neoforge-1.11.2.jar）接受，日志零 Unknown command**。
- 测试：pause/resume 配对、无移动不 pause、失败路径也 resume。

**T3 死亡播报直发（bridge+brain，协议 1.2→1.3）**
- bridge：新工具 `chat.send {string 1..256}`（`ChatTools`+`ChatContracts`）——进程内 `ClientPacketListener.sendChat`（vanilla 聊天屏 ENTER 的同款入口，死亡屏免疫）；守卫与 input.* 同款（-32011/-32012/-32010 各一次计费），新增 `PermissionContracts.Action.CHAT`（仅 observe 拒绝；screen 状态刻意不参与判定——屏幕免疫就是它的存在意义）。
- brain：`LoopClient.say()`（chat.send + echo 登记 + 命令锁 + 旧 jar -32601 自动回落 command）；`AgentLoop._broadcast_direct` 接线；`DeathReflex` 播报改走 `broadcast_direct`。
- 旧 jar 实测：chat.send 回 -32601（预期），回落路径单测覆盖。

**T2 移动自然转头（bridge）**
- 根因（不是 TurnController）：M4-rerun 130 格长走审计日志零旋转写入 + 用户观察 → **Baritone 该构建行走不转头**（WASD 组合平移），相机冻结是"没人转头"。
- 修复：`MovementLook`（每 tick，`ClientTickEvent.Post`）——水平速度 ≥0.05 b/t 时按速度矢量方向 300°/s 固定角速度只写 yaw（`LookTools.applyYaw`，pitch 不碰）；让位规则：TurnController 活跃 turn（显式 lookAt/dig 瞄准）优先、死区 2°（与 Baritone 自身旋转目标一致时不写，天然不打架）；config `movement_look` 开关（默认 true）。
- `getStats` 增报 yaw/pitch（StatsSnapshot 扩两个字段，增量不破坏旧 brain）；`UnstuckReflex` 扇形基准改用当前 yaw（旧 bridge 回落 0°）。
