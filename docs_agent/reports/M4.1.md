## 1. 五缺陷修复与证据

### T1 聊天连发命令竞态（🔴）——已修复，真机 PASS

**根因（两层）**：
1. 命令串行锁只存在于 `LoopClient`（loop 级）；`m4_flee_walk_probe.py` 用 raw `BridgeClient` 建 `Primitives`——探针的 #goto 与调度器的 #stop/#goto 并发，两条 T→text→ENTER 序列在 wire 上交错，两段文本进同一个聊天框合并成 `stop#goto`（M4-rerun 00:41:01 `Command not found` 事故）。
2. `command()` 时序全靠拍定时数（0.4/0.3/settle），无"聊天框确实打开/关闭"的确认。

**修复**：
- 锁下沉到 `BridgeClient.command`（客户端级 `_command_lock`，覆盖一切发送方；LoopClient 锁保留，锁序 loop→client 无死锁）。
- 确认时序：T 后轮询 getGuiState 等聊天屏打开——**被其他 GUI 占用即拒绝盲发**（顺带消灭"文本盲发进任意 GUI + ENTER 误点按钮"的旧风险）；ENTER 后等聊天屏关闭——关不掉（发送失败）按 ESC 丢弃残留防串扰并报错。身体回包无 `screen_open` 字段（mock/旧身体）自动退回 M2-D 定时等待。
- `m4_flee_walk_probe.py` 的 Primitives 改挂 `agent.tools_client`。

**证据**：pytest `TestCommandRace`×3（并发/背靠背不合并、占用拒绝盲发）；真机（新 jar）10 条 #stop/#goto 连发 5.19s，游戏日志 0 条 Command not found、bot 位移 14.9 格。旧 jar 上客户端侧修复已独立生效（Phase1 PASS）。

### T2 移动不转头 / 固定视角平移（🔴）——已修复，真机 PASS

**根因结论（spec 要求的冲突裁决）**：**不是 TurnController 与 Baritone 互相覆盖**——TurnController 收敛即注销、自过期上限 360°/speed+1.5s，不存在"驻留每 tick 写入"。铁证：M4-rerun 00:48:16–00:49:07 的 130 格 Baritone 长走全程，`sirius_bridge.log` 审计里**零条 look/lookAt/turn 写入**（只有 getStats/world.query 轮询）。真相是 **Baritone（baritone-standalone-neoforge-1.11.2.jar 构建）行走自身不转头**——用 WASD 组合平移，相机全程冻结，这正是用户看到的"固定视角平移"。

**修复（bridge `MovementLook`，"移动自然转头"由我们补位而非赌 Baritone）**：
- 每 tick（`ClientTickEvent.Post`）：水平速度 ≥0.05 b/t（≈1 m/s）时，按**速度矢量方向**以 **300°/s 固定角速度**只写 yaw（pitch 不碰——不扰动瞄准）。
- 让位规则（不与任何主动旋转打架）：TurnController 活跃 turn（显式平滑 lookAt / dig 瞄准）优先；与运动方向夹角 ≤2° 死区不写（若 Baritone 将来自己转，目标一致时控制器自然静默）。
- config `movement_look`（默认 true）可一键关闭；`getStats` 增报 yaw/pitch（诊断数据源 + unstuck 扇形基准升级为当前朝向）。

**证据**：冒烟 MovementLook 纯决策 5 例（静止/垂直不动、步进 15°/tick、短路径、±180 环绕、慢速不过冲）；真机 #goto 40 格 43 样本：yaw 覆盖 10 个度值（270→314 随路径转向），运动中 |yaw−运动方向| **中位 0°、P90 8°、max 16°**——头随身体转动。

### T3 死亡播报未上聊天（🟡）——已修复，真机端到端 PASS

**修复**：bridge 新工具 `chat.send`（`ChatTools`/`ChatContracts`）——进程内 `ClientPacketListener.sendChat`（vanilla 聊天屏 ENTER 的同款入口），死亡屏等任何 GUI 都无法屏蔽。这是"操作型功能入 bridge"的又一例（look/dig 先例）：诚实输入管道（T 键）物理表达不了的动作，在 vanilla 自己的层做。守卫与 input.* 同款（-32011/-32012/-32010 各一次计费），新增 `PermissionContracts.Action.CHAT`（仅 observe 拒绝；屏幕状态刻意不参与判定）。brain 侧 `LoopClient.say()`（chat.send + 自回显登记 + 命令锁 + **旧 jar -32601 自动回落 GUI 路径**）；`DeathReflex` 播报改走直发。**低血警报同样改直发**（T6 压测实证"低血警报发出前毫秒级死亡、死亡屏占 GUI 吞掉 T 键"窗口期竞争）。

**上轮"播报×3"矛盾复查结论**：M4.md 的 ×3 验的是 wire 层 SENT；游戏聊天可见性当时依赖轮询抢在死亡屏渲染前——时序侥幸，M4-rerun 的观测（wire 已发、聊天无行）才是稳定真相。本轮端到端：**重启后世界恰停在死亡屏——挂真实调度器，播报 `<Sirius_test> 我死了……死亡位置约 (2,64,34)。等你指示，我不会自动重生。` 经 chat 事件实证真实进入游戏聊天，且死亡屏保持打开不自动重生**。

### T4 input.key 长按打空令牌桶（🟡）——裁决：语义本就正确，无需改码

**实测裁决（推翻 M4-rerun 推断）**：源码所有计费点（input.key/text/mouseMove/click/dig）都是 `tryAcquire(1)` 按调用计费；部署 jar 真机实测：**1500ms SHIFT 长按 + 19 并发 tap 全部 19/19 通过**——一次长按只占 1 令牌坐实，"按 tick 计费"证伪。当时 -32010 的真实成因：演示脚本自身不等待的管道化并发调用打爆桶（input.* 主线程逐个执行 ~50ms/个，await 串行调用 ~5/s 永远追不上 20/s 补充，只有 fire-and-forget 齐发才可能打穿）。反射层全部 await 串行（换气 ≤2/s），无桶风险。限流器本身工作正常（30 并发齐发观测到拒绝）。

### T5 cooperative 反射 vs Baritone 拉锯（🟢）——已裁决并实现

**裁决**：cooperative 反射生效期间发 `#pause`（Baritone 保目标停下按键），act 收尾（含异常路径 finally）`#resume` 续走。优于 #stop+不重启：walk 原语的续走语义完整保留；preempt 反射已 #stop 撤目标后，迟到的 #resume 是无害空操作。**真机可用性实证**：Baritone 聊天回执 `[Baritone] > pause` → `Paused`、`> resume` → `Resumed`（1.21.1 + 该 standalone 构建）。配对条件：仅 `movement_active`（有上层行走任务在跑）时 pause，站着换气不多此一举；幂等 + 失败只记日志（暂停不成不阻断保命动作）。

## 2. 新验收 1：T6 分段存活压测（反射层独立存活）

**方法**（主管分段制修正版）：每场景独立 120s，AgentLoop 只挂调度器零任务消费（零 VLM token）；场景前 `/effect give @s instant_health` + `saturation 999 255 true` **消除饥饿变量**（实测作弊开启成功——世界此前作弊关闭，探针经 GUI 自动化「对局域网开放+作弊:开启」授权）；每 10s 采样 health/air/位置/yaw/反射计数；死亡即记归因 + GUI 点「重生」（探针扮演玩家；DeathReflex 本体不自动重生的承诺不变）。

| 场景 | 结果 | 反射触发 | health 轨迹 |
|---|---|---|---|
| 怪群围攻（3 僵尸+2 溺尸，持续补怪） | **DEATH t=20s**（归因见下） | 逃离×2（均到位）、低血×2、死亡上报×1 | 17→8→0 |
| 深水（tp 最深水格，浮出即再按回） | 首轮 **DEATH t=74s** → **修复后回归 PASS**（换气×14、2 分钟存活、0 死亡；health 最低 4.3） | 换气×7（首轮）/ 修复后×14 全成功 | 20→13→0 / 修复后存活 |
| 火（脚下点火，15s 复燃） | **PASS** | 着火撤离×1、低血×1 | 19~20 振荡 |
| 卡位（1 宽 2 深坑+围壁，注入 W 意图） | **PASS** | 脱困×20（每冷却期一次爆发） | 恒 20 |
| 综合混灾（怪+火+水） | **PASS** | 换气×10、着火撤离×1、逃离×3、低血×1 | 最低 7.7 存活 |

**死亡归因（2 次，全归因）**：
1. 怪群围攻：反射链**全部正确触发**（两次逃离均到位、两次低血警报、死亡直发播报），仍死——裸装无武器 bot 被 5 只怪轮番贴身，L1 禁攻击（安全约束）+逃离冷却 6s 期间再次贴身。**工程结论：这是设计边界不是缺陷**（反射层是保命脊髓不是战斗模块；对策是 L2 自卫/装备，留独立轮次）。
2. 深水（首轮）：换气反射"按 400ms→歇 500ms"低占空比在深水柱净上浮≈0（按住上升段被歇息下沉段吃光，19 次未脱离→10s 封顶→轮次间隙继续掉氧）。**已修**：按住 800ms 等释放再复查（间隙仅一次 getStats 往返），修复后深水场景回归 PASS。佐证：综合混灾的浅水换气 ×10 首轮就全成功。

**边界声明（诚实口径）**：反射层职责 = **突发危险的即时自救**（溺水/着火/围攻/卡位）；慢性消耗（饥饿/长期低饱食）不在职责内（本压测以饱和效果消除该变量）。压测中"低血→秒死"窗口期还实证了低血警报被死亡屏吞 T 键的竞争——已随之改直发通道。**backlog：进食反射**（检测饥饿+库存有食物→自动吃）是合理的 L1 未来成员，属执行器层协作范畴，留 M4.2/M5。

**附带实证**：死亡播报直发在两次真实死亡中均上聊天；GUI 重生点击两次成功；火/卡位场景为此前"环境受限未真机"的补验（M4.md 遗留）。

**压测引出的第二个修复（safe_command）**：深水回归轮暴露——低血反射的 `#stop` 被 GUI 占用拒绝（-32002）时抛异常，会**跳过后续的直发警报与 urgent 注入**。修复：preempt 反射（低血/撤离/逃离）的 `#stop` 统一走 `ReflexScheduler.safe_command`（失败只记日志，保命链不被单条命令打断）；回归单测 `TestM41SafeStop`（#stop 拒绝时警报仍直发）。
