## 3. 新发现与已知边界（未改码，留待下轮处理）

1. **聊天连发命令输入竞态（新，疑似产品缺陷）**：逃离反射紧连发送的 `#stop` 与 `#goto` 在聊天输入层被合并为 `stop#goto …`（游戏日志 `Command not found: stop#goto`，00:41:01），逃生命令实际未执行，bot 被围殴致死。上轮验收夜跑的两次"撤离途中被射死"不排除同因。建议下轮检查 LoopClient.command 的 settle/输入流水线在连发时的原子性。
2. **input.key 长按令牌桶放大（新，运维/契约）**：duration_ms=1500 的长按会把 ~20/s 的 input.* 令牌桶一次打空（长按疑似按 tick 计费），反射的 SPACE 长按与外部 SHIFT 长按叠加必然触发 -32010。建议文档化"长按≈duration_ms/50 个令牌"或改为按住语义单计费。
3. **死亡播报未上游戏聊天（与 M4.md 记载存在出入，需下轮复查）**：本轮挂尸触发的死亡播报在 wire 层已发（SENT 实证），但游戏聊天无此行——**死亡屏打开时 T 键无法唤起聊天框**，输入被吞。上轮验收记录"死亡播报 ×3 进游戏聊天"，与本轮观测矛盾：或是上轮时序侥幸（轮询抢在死亡屏渲染前），或是当时走的其他通道。值得专门复查死亡播报的可达通道（如改用不受 GUI 屏蔽的发送路径）。
4. **探针间隙无保护死亡 ×6（已知边界，N=6 加重实证）**：00:37:27 / 00:39:13 / 00:41:05（竞态致死）/ 00:44:07 / 00:46:19 / 00:49:36——全部发生在调度器未挂载的探针切换间隙（出生点夜间怪群 + 两处水域）。"反射层不是保命外挂"的语义被反复验证；对长驻产品而言这是部署形态问题（agent 进程应常驻），不是反射层缺陷。
5. **窗口再次被最小化（已知运维坑复发）**：00:47:20 前后 mouseMove NaN/点击无效，ShowWindow(SW_RESTORE) 恢复。真机运维清单应固化为测试前置步骤。
6. **cooperative 反射不撤销 Baritone 目标（边界澄清）**：GoalBlock 指向水下时换气反射与 Baritone 拉锯（浮起→再按下循环）。walk_briefly/#goto 的目标选择若避开水下格即可规避；产品语义内。
