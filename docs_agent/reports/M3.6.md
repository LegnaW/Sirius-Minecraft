## 关键决策与理由

1. **drops 报告 = 新出现实体（挖前快照 diff），不是"4 格内全部"**：spec 写"新出现的 item 实体"。若只扫 4 格内全部，别人先掉的掉落会混进本次报告、进而被 brain 的匹配集捡走（违多人服礼仪）。挖前在主线程快照 uuid 集，破坏后 diff——别人的绝对不混入。FakeWorldBridge 同契约镜像，既有礼仪测试（foreign_drops_untouched）零改动通过即为证。
2. **drops=[] 与 drops 缺失语义分开**：字段在=新 bridge 的实测结论（空=真没掉/已被捡，跳过拾取清扫省一次走位）；字段不在=旧 jar v1.2（brain 回落 registry id 匹配）。`_extract_drops` 用 None/[] 区分，话术分别为"，无掉落"/不提。
3. **延迟窗 20 tick（1s）保留 + 预算护栏**：评估结论——dig 本身秒级（真机 dirt 3.5-4s），1s 尾部可接受，不压到 10-15 tick（spec 允许但没必要）。护栏：broken 落在 timeout_ms 最后 1s 内时跳过等待（brain 侧 call 默认 30s RPC 超时会赛跑——宁可回旧形态也不让成功的挖掘超时）。冒烟断言 10≤ticks≤20 与半径=4。
4. **sleep 放 WS handler 线程**：dig 本就是同步 RPC、brain 串行驱动，同连接后续帧晚 1s 无碍；比"主线程调度再回捞"简单一个数量级。sleep 中断/世界退出/主线程查询失败一律返回 null（省略字段）——掉落报告 best-effort，绝不弄失败一次已成功的挖掘。
5. **pickup 缺省"捡全部"只靠描述约束礼仪**：运行时无法判定掉落归属，多人服礼仪话术（"只捡明确属于自己活动的掉落物"）写进工具描述与系统提示，靠 VLM 层把关；指定 item_ids 时仍是注册名精确匹配（硬约束）。
6. **HelloAckFrame 只进 frames.py 不进 schema 导出**：hello 请求帧一直在 client.py（握手不是工具调用协议），schema 导出（FRAME_MODELS）从不含握手帧——只补 ack 模型 + 客户端识别，别硬塞导出链（spec/任务书一致）。协议版本不动 1.2。
7. **观察纪律措辞**：精确到"答案取决于当前世界状态"（触发条件），豁免三项显式列出（闲聊/知识问答/引用已有工具结果的汇报）——避免"你好"也触发查询（M3-C 真机"你好"1 步闭环的既有行为不回退）。

## 实现要点 / API 笔记

- **drops 链路**：bridge `startDig` 快照 → monitor FINISH(broken) → WS 线程 sleep 20 tick → `itemFactsNear`（主线程，EntityFact+注册名，同 world.query entities 路径）→ `aggregateDrops`（LinkedHashMap 保首现顺序，count 按 `Math.max(1, count)` 累加）→ `digResult(..., drops)`。brain `_translate_dig_result` → `_StepResult.drops` → `_collect_drops(drops=)` 匹配集。dig standalone 话术也带掉落（VLM 可直接回答"挖到了什么"）。
- **fake 与真机的一个真差异**：真机 20 tick 等待窗内掉落可能已被玩家磁吸（挖头顶方块实测 drops=[]，诚实为空）；fake 同步无延迟不体现——测试关注契约形态，不为此时序建模。
- **pickup 计数口径**：沿用 T7 语义——实体消失件数（不是物品数）。真机 drops 报 3 个 dirt（2 实体）→ pickup 报"已捡起 2 个"，两口径各自成立。
- **协议契约**：`drops` 仅 broken 且新版 bridge 才有；already_air/timeout/blocked_*/not_digging 一律不带。audit 行 `drops=N`（N=聚合条目数）。
- **HelloAckFrame 防漂移**：test_frames 用线上原文 `{"type":"hello_ack","ok":true,"protocol_version":"1.0"}` 直接过模 + dump 后字段集恰为三个。
