## 关键决策与理由（与 spec 的偏差逐一说明）

1. **事件订阅不带 min_level**（spec/任务提示说"订阅 min_level"）：bridge 侧订阅是**单槽替换语义**（`ClientSession.subscription` 单值，第二次 subscribe 覆盖第一次）——分两次订阅会让 chat（INFO）被 CRITICAL 过滤掉。改为一次订阅全类型 `["chat","death","fire","health_low","drown"]` 不带 min_level；危险判定靠事件类型本身（这四个事件天然只有 CRITICAL）。
2. **眼在水中信号**：getStats 实测无水/火/朝向字段（schema v1.2 字段：health/food/saturation/air/xp/position/dimension/game_mode/effects/alive）。用 world.query(blocks, filter=water, range=3) 查眼位方块（floor(x), floor(y+1.62), floor(z)）；**只在 air<300 时才查**（空气满=没在淹，省一次查询）；结果 truncated 时保守为 True（M3.5 T5a 教训：截断发生在排序前，"眼位格不在结果里"不可信，而被水包围时截断恰是常态）。
3. **entities 加 width（超出 spec T1 字面）**：spec 的 flee 危险半径公式（碰撞箱宽推攻击距离）brain 侧需要 width 输入，payload 没有就没法算。与 category 同为纯增字段（null/0 不输出），协议版本不动（1.2，capabilities 实测确认）。
4. **危险半径 = width/2 + 1.5**（Numen Menace 简化）：不查怪物 attribute/实际攻击距离。僵尸/末影人 0.6 宽 → 1.8 格。**远程怪（骷髅）偏保守**——实测骷髅在 30 格外就把 bot 射死，flee 不会触发（贴身半径才触发），这是已知简化点；低血反射是远程伤害的实际兜底（真机验证过）。
5. **unstuck 扇形基准取 0°**：当前 yaw 读不到（getStats 无朝向）。137°×k 扇形从任意基准出发仍是探索性爆发，跳跃是主要脱困手段；转错方向只是多试一段。
6. **fire 无水时的"反向"** = 最近 3s 运动速度的反方向（getStats 拿不到火源方向）；无近期运动取 +X。
7. **等级切换不持久化**（任务指示的简单做法）：只改内存 `scheduler.level` + LoopConfig.reflex_level 启动默认；重启回 self_preserve。播报确认"本能说明将随下一个任务生效"——系统提示按任务生成，运行中任务的提示不热改（历史一致性优先）。
8. **urgent 排队 drain 而非直插活动 messages**：vlm.chat 在工作线程里遍历 messages，并发 append 有竞态；〔紧急〕进 pending 列表，在每轮 VLM 调用前与任务开头 drain（任务死了自动留给下一任务——真机死亡场景正需要这个）。
9. **"主人"近似为 16 格内最近的其他玩家**（speaking_look）：单机世界里没有第二玩家，此反射真机自然不触发（entities 里只有自己，uuid 自识别后排除）。
10. **preempt 不复用急停回话路径**：`request_preempt(reason)` 独立入口——end_reason 记 `preempt`、run.result 带"被反射 X 抢占"、`_finalize` 不播报（反射路径自己上报），与"停下"的 STOP_REPLY_TEXT 完全分流。

## 实现要点 / API 笔记

- **调度器生命周期**：`AgentLoop.run()` 里 `_spawn(scheduler.run())` 与任务队列消费并行；`run()` 的取任务循环有 `while scheduler.busy` 门（反射 act 期间不开新任务——先归位再做事）。`shutdown()` 先 `scheduler.stop()` 再取消后台任务。
- **注册序即优先级**：death → health_low → fire → flee → breath → unstuck → speaking_look；每轮采样后按序问 `can_run`，**首个 True 胜出并 break**（层内单候选）。真机实测这个顺序的代价：flee 的 10s 撤离行走期间 health_low 事件只能等（单候选阻塞）——bot 被骷髅追射时低血上报延迟了 ~10s。若后续要更细，可把"通知型"（health_low/death 的上报）与"动作型"（撤离行走）分层。
- **等级门控**在调度循环（`chain.level.value > self.level.value` 跳过），L0 下七条全跳过；danger 事件 handler **不门控**——〔危险〕行照进 behavior_log（L0 关动作不关感知）。
- **边沿自持**：fire/health_low 事件置位 → act 开头清位（再触发靠下一条事件，bridge 侧本有 5s 边沿冷却）；death 用 `_reported` 闩 + 复活重臂（getStats alive=True 过 5s 宽限期才清闩，防轮询/事件竞态）；flee/unstuck/health_low 各带 6/6/8s 本地冷却。
- **死亡时其余反射不动作**（`not s.dead` 门控）：真机教训——溺死的尸体还会按 SPACE 刷了 18 次简报；修复后 breath/unstuck/flee/speaking_look 全部加 dead 守卫。
- **位置窗** `deque(maxlen=max(12, 6s/poll_interval))`：固定 maxlen 在快轮询（测试 0.05s）下装不满 2s 判定窗——按轮询间隔定容。
- **walk_briefly**（反射专用短途走）：`#goto` + 轮询到位，超时即收——不走 Primitives 的长超时/看门狗契约（反射的撤退不恋战）。flee 的 8 格撤离在真机偶发"超时仍在撤离"（追击/地形），行为正确只是没走到 2 格判定圈内。
- **行为简报格式**：`〔危险〕…`（事件感知，L0 也进）与 `〔本能〕…`（反射动作，act 结束才写——先归位再宣布；act 中途死亡/被取消则该行不写，这是设计不是 bug）。flush 时合并成一条〔本能反应〕消息，替换式注入（历史里恒一条）。
- **java 侧**：`MobCategory.name().toLowerCase(Locale.ROOT)`（monster/creature/ambient/water_ambient/water_creature/misc…，注册表数据——模组怪自动归 monster）；`EntityDimensions.width()` 是 record 访问器。
