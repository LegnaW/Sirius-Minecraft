# Sirius · 天狼星 —— 分层 Agent 架构设计思路

> **Sirius**：夜空中最亮的恒星，实际是一个双星系统——天狼星 A 明亮耀眼，天狼星 B 是白矮星，暗弱却极致致密。一明一暗，**但都是恒星**：不是主星与卫星，而是两颗对等的星围绕共同质心互相绕转。
>
> 这就是本项目的关系宣言：我们与被造的它，如双星绕行。也是架构的隐喻——明者是规划器（大模型），暗者是执行器（小模型，小而致密）；而"我们造了她，陪伴让她活过来"。

## 0. 我们要解决什么

Mindcraft CE 已经是一个能干的 Minecraft AI 玩家：能对话、挖矿、合成、战斗、协作，甚至现场写代码解决新问题。但它的架构是**单层平铺**的——一个模型包办从闲聊到规划到执行的一切。这带来四个核心痛点：

1. **一心不可二用**：bot 在挖矿时，玩家的聊天要排队等它忙完
2. **上下文互相污染**：任务执行的冗长输出和玩家闲聊混在一起
3. **成本错配**：回一句"哈哈"和制定打怪策略，用同一个（贵或弱的）模型
4. **能力封顶**：感知和动作都封死在原版协议里——Mod 世界对它是隐形的，记忆只有一段自由文本，遇到没见过的任务只能现场重新发明轮子

我们的目标是一个**随游玩时间自主成长、能玩 Mod 服务器、始终能和玩家自然对话**的 AI 伙伴。

## 1. 核心理念：像人一样分层

人类玩家的大脑不是单一循环：

- **手**会自己躲火（脊髓反射，不过脑子）
- **脑**规划"今天下矿挖钻石"并分解步骤
- **嘴**同时还能和朋友闲聊

对应我们的三层认知架构：

```
规划器（大模型）—— 社交与决策：和玩家聊天、理解意图、分解任务、监督执行
执行器（小模型）—— 专注于做事：领任务、调工具、汇报结果
反射层（无LLM）  —— 本能反应：保命、自卫，永远最高优先级
```

**一句话原则：规划器主见任务、少见方块；执行器只见方块、不见玩家。**

两端各取所长：大模型贵而慢但聪明——只花在理解和规划上；小模型便宜而快——专心执行。执行时规划器完全空闲，随时可以和玩家聊天、接收新命令。

### 例外：快车道

原则太死板会变得笨拙。"把剑扔给我"这种一秒钟的事，走完整的派单流程反而荒谬。所以规划器保留一组**原子短时命令**直接执行（快车道），持续性任务才派发（慢车道）。就像店长也会自己顺手递个东西，但不会自己去搬整仓货。

### 例外：亲手模式

当所有工具都不够用（比如要操作一个 Mod 机器的界面）时，规划器可以**亲自上手**：看截图、点鼠标、按按键，用最原始的方式完成任务。这很贵很慢，所以只作为应急——但应急做完的事不会浪费，见第 4 节。

## 2. 协作机制：任务、中断与请示

两层之间的沟通语言是**任务卡**：规划器把"帮我搞点装备"这样的模糊意图，翻译成一张结构化的卡片——目标、成功标准、约束、可用工具、中断策略。执行器拿到卡片后自主工作，不需要手把手。

### 中断：三档语义

现实里打断一个人有不同方式，对应三种设计：

- **DEFLECT（偏转）**："停一下，听我说"——做完手头这一步就停下来听。成本最低，最常用
- **PAUSE（暂停）**："先歇会"——保存进度，稍后可恢复。但进度只能在步骤边界保存（挖到一半的方块没法存档，"已挖 12/30"可以）
- **CANCEL（取消）**："别做了"——丢弃一切，从头再来

关键认知：整个系统的中断是**协作式**的——不杀线程，只是设置标志，由代码中的检查点响应。所以"能不能立刻停下"取决于当前原子操作的粒度。而最紧急的事件（溺水、着火）根本不惊动任何模型——反射层直接处理，**先跳，再解释**。

### 请示：永不空转

执行器遇到拿不准的事（"发现钻石，要挖吗"）会**请示**规划器，但请示带默认行为和超时——规划器 30 秒没回，就按默认继续。这保证了两个优雅性质：**执行器永不空转等待，规划器永不被迫立即响应**。

## 3. 记忆：四类型、四层、双源、双模态

现有"记忆"只是一段自由文本。我们要的是像人一样的记忆系统。

### 先分类（四种记忆）

| 类型 | 例子 |
|---|---|
| 工作记忆 | 正在做什么、进展如何 |
| 情景记忆 | 昨天在哪被苦力怕炸死 |
| 程序性记忆 | 下矿要先垫脚防岩浆（**学会的**） |
| 世界知识 | 创意矿石需要铁镐（**查来的**或**经历的**） |
| 玩家记忆 | "他想要钻石剑"、"他喜欢晚上下矿"（**关于人的**） |

最后一类以前被忽略了：陪玩 bot 的记忆不能只有世界中心的（方块/任务/Mod），还必须有玩家中心的——记得玩家的喜好、习惯、随口提过的愿望，是"越处越懂你"的基础。

### 再分层（按访问成本）

```
工作记忆 ──就在上下文里（最贵，占token）
活跃记忆 ──少量精选卡片注入上下文
长期记忆 ──向量数据库，需要时检索
知识库  ──向量数据库，同上
```

近期的、重要的记忆自动待在上下文里；其余沉入向量库，用到再捞。活跃层有硬预算，靠"新近度×重要度×使用频率"的得分决定谁上位谁退场。

### 双源知识：查来的 + 学来的

Mod 知识尤其关键——模型预训练里根本没有这个 Mod。传统做法是导入资料库（只读），但**我们要的是拟人**：真人玩家也是被炸几次才知道这个怪的习性。所以知识库同时接受：

- **导入的**（数据包、wiki，权威，置信度 100%）
- **习得的**（游戏经历中提炼，初始不确定，随印证/反驳演化置信度）
- **玩家教的**（玩家纠错是最高权威）

错误认知不可怕，可怕的是不可纠正。习得的知识永远带置信度注入（"可能60%确定：这矿石会爆炸"），且每次经历都可能印证或反驳它。矛盾积累到一定程度，规划器甚至可以**设计实验主动验证**——"用不同等级的镐各试一次"。这是从被动学习到主动学习的跨越。

### 双模态：文字 + 图像

文字描述是有损压缩，原始图像是无损证据。"紫色旋转方块"六个字，远不如一张照片信息量大——尤其对视觉模型，**教它认识没见过的东西，最便宜的方式就是给它看一张样例图**。所以记忆卡片可以附图像（原图存档/裁剪主体/全图缩略三档，可配置），检索仍走文字，图像是命中后的"可升级载荷"。知识起冲突时，还能翻出当时的原始截图"对质"。

### 记忆也会"想"：反思与遗忘（借鉴 N.E.K.O）

记忆不该只是被动堆放。桌面 AI 伴侣项目 N.E.K.O 给出了两个动人机制：

- **对话式验证**：AI 把自己观察到的假设自然地说出来（"我发现你好像喜欢晚上下矿？"），用玩家的反应来确认或推翻——社交本身就是认知实验。确认的观察逐渐沉淀为人格的一部分（"他记着我怕岩浆"），人格因此是活的，而非一段静态设定
- **遗忘的数学**：每条知识的"强化"与"反驳"各自带半衰期衰减——好事渐渐淡忘、教训记忆犹新；长期无人印证且屡被反驳的知识会被制度化地归档。**记得住也忘得掉，才像生命**

## 4. 技能沉淀：越玩越熟练

人类玩家的成长路径：第一次做某事手忙脚慢，熟了以后变成肌肉记忆。对应我们的 skill 系统：

```
工具不够用 → 规划器亲自上手（贵、慢，但全能）
          → 行为轨迹完整记录
          → 复盘提炼成参数化"技能"
          → 验证通过后入库
          → 执行器以后直接按技能执行（快、便宜、不需理解原理）
```

技能有生命周期：验证两次才转正；成功率下滑（Mod 更新改了界面）就标记退化，上报重学。技能描述也进向量库，派单时自动检索匹配。

于是执行器的工具形成三级结构：**原子命令（天生的）→ 已验证技能（学会的）→ 上报规划器（开新路）**。整个系统随游玩时间自主成长——而且成长对玩家可见（"我学会用那个搅拌机了！"），这本身就是最拟人的体验。

## 5. 眼与手：给机器人一具自己的客户端

### 5.1 身体选型的最终裁决：独立游戏程序

让 AI 玩 Minecraft 有三具身体可选，我们走了完整的评估弯路：

| 方案 | 优势 | 致命局限 |
|---|---|---|
| mineflayer（协议模拟） | 轻量、无人值守 | 没有屏幕；Mod 内容不可见不可操作 |
| 服务端假玩家（Numen 路线） | 原生 Mod 兼容、联机经济学好 | **无像素**：看不到玩家皮肤、感受不到 boss 的视觉冲击，陪玩缺共同视觉语境；**服务端必须装 Mod**，无法带着 bot 进别人的服务器 |
| **真客户端（选定）** | **亲眼所见、亲手所点、进任意服务器** | 资源开销大、需自研客户端寻路 |

决定性论据有两个，都指向"陪玩"这个产品本质：
1. **共同视觉体验**：陪玩的 bot 必须能看到你的皮肤、看到 mod boss 有多震撼——聊天时天然共享一块视觉语境，沟通才不缺信息。服务端假玩家制度性地做不到
2. **可携带性**："带着 AI 朋友进别人的服务器玩"要求 bot 对服务器就是个普通玩家——服务端不能依赖任何安装

机器人拥有一个**独立的 Minecraft 客户端**（装着和服务器一致的 Mod），像真人一样排队进服、看画面、动鼠标键盘。

### 5.2 架构：Bridge Mod（眼与手）+ 后端大脑

```
机器人客户端（真游戏程序 + Mod）
  Bridge Mod：
    眼：screenshot（它亲眼所见）/ getGuiState / world.query
    手：input.*（鼠标键盘注入——像人一样操作）
    反射层：客户端本能链（竞价调度，借鉴 Numen）
       ↕ MCP 式双向协议（工具调用 + 事件主动推送）
后端大脑（本文档全部设计）
    规划器/执行器 + 分层记忆 + Skill 自学习
```

意外之喜：这个方案同时解决了三具身体的全部痛点——Mod 内容渲染天然正确（客户端装同款 Mod）、**Mod GUI 可看可点**（GUI 就在它屏幕上，mineflayer 和假玩家都做不到这一点）、进任意服务器（服务端零安装）。

代价（直视）：每 bot 一个客户端进程的资源开销（无头化摊薄）；客户端寻路需自研（Baritone 证明纯客户端寻路可行，Numen 寻路文档为设计参考）；输入注入需防抖与保真设计。

### 5.3 与 Numen 的关系：错位共存

Numen 是优秀的前人工作，但定位不同：它做**服务器里的 NPC/管家**（服务端安装、服主运营），我们做**陪你进任何服务器的 AI 队友**（客户端、私人、跟着你走）。

它是我们最重要的**设计供体**（详见技术规格 §8），且关系错位而非竞争：同一个大脑后端理论上既能驱动客户端身体也能接管 Numen 身体——"大脑不绑死身体"原则保留，如今有了真实的第二消费者。

### 5.4 安全与中立（承自 Bridge 设计）

Bridge Mod 本质是"合法远控"，安全内建：默认仅 localhost、token 握手、权限分级（观察/世界操作/界面操作）、输入限频、审计日志。协议遵循"输入标准化、感知原语化"——Mod 是哑管道，怎么用交给 agent 开发者。

## 6. 陪伴感：主动、知情、有人格（借鉴 N.E.K.O）

拟人陪玩的最后一公里不在任务能力，而在**关系体验**。桌面伴侣项目 N.E.K.O 定义了这个领域的标准，我们要在游戏里做到对应的版本：

- **主动陪伴**：bot 不是有问才答的客服。规划器空闲时会主动开口——看到震撼的 boss 就惊叹、玩家深夜还在肝就唠叨两句、路过上周一起死过的地方会提起。触发源：视觉事件（截图发现新东西）、时间（现实时间感知："都凌晨两点了"）、记忆回调（场景与某条玩家记忆相关）
- **共视觉**：因为它有一具真客户端（见 §5），它看到的 boss 和你看到的是同一个画面——"你看那个特效！"是真实的共同体验，不是编的
- **活的人格**：人格通过被确认的观察逐渐固化演化（§3 反思层），一致性不等于一成不变。用户可以用一张**人设卡**（Markdown：身份/性格/说话风格/示例对话/底线）定义她的起点——但起点不是终点：卡片是用户写的种子（永不衰减），习得人格是她活出来的部分（可演化可遗忘），两者在对话里自然融合。玩家口头说的"你以后别那么话痨了"会被记住并生效，但我们不会偷偷改写你的卡片文件
- **玩家的记忆**：记得玩家的喜好、习惯、随口提过的愿望（§3 第五类记忆），"越处越懂你"

## 7. 成长闭环（全图景）

把所有系统串起来，得到一个自我提升的循环：

```
执行器遇到不会的 → 上报规划器
  → 规划器亲手做（必要时借 Bridge Mod 的眼和手）
  → 经验沉淀：世界知识进知识库（可被修正），操作经验进技能库（可被复用）
  → 记忆与技能在派单时自动检索注入
  → 执行器下次直接就会了
```

玩家看到的，是一个**越来越懂这个服务器、越来越熟练、记得住发生过什么**的伙伴——这就是"拟人"的工程表达。

## 8. 路线图：双星并行，M3 会师

开发遵循四原则：**薄切片先通再逐层加厚**（早期就有能跑的整机）、**风险前置**（输入注入保真度最先验证）、**协议先行**（契约冻结后两条线并行）、**每步有真人可看的演示**。

```
sirius-bridge（身体轨，Java）：M1 眼 → M2 手 ──── M3 会师 ──→ M4 反射+寻路
sirius-brain（大脑轨，Python）： M0 协议冻结 ──（对 mock 身体开发）→ M3 会师
```

关键洞察：**大脑不需要等身体**。协议冻结后，大脑对"回放真实协议帧的 mock 身体"开发全部逻辑（规划器/执行器/记忆），sirius-bridge 并行造身体，M3 时切换——协议层保证切换成本趋近于零，这也是"大脑不绑死身体"原则的第一次实战。

三个阶段的目标递进：**M0-M3 证明它能活，M4-M8 证明它好用，M9 证明它像人。**
